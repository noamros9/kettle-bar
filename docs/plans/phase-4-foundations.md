### 1. Summaries (#18)
- **Program paragraphs**, written by hand: one `about` per program in `programs.config.js` (all 29). Each says
  what it trains, how it's built, how it gets harder, and who it suits. The program page shows the
  paragraph instead of the blurb; program cards show its first sentence.
  - For frozen Three-Split 60, `about` comes from the config like its other descriptive fields. Its days
    are untouched (ADR 1).
- **Day lines**, generated by a new pure function `daySummary(day, program, cat)` in `app/summary.js`:
  - **Line 1, the shape:** the focus and what the day is made of, e.g. "Chest, back & abs: 5 exercises in
    straight sets, then abs."
  - **Line 2, the emphasis:** the muscles worked most, and what this level changes, e.g. "Most work for
    chest, lats and triceps · Level II: more reps."
  - Swapped days say so. The lines show on the day page under the workout's name.
- Files: `programs.config.js`, `program-builder.js`, `app/summary.js`, `tests/summary.test.js`, `app/views.js`, `build.js`, `package.json`.
- **Test first:**
  - `daySummary` on hand-made days: straight sets, a mix of formats, Level I vs a lever at Level II/III, a swapped day.
  - A builder test: every program has an `about` of 3–6 sentences.
- **Done when:** every program page shows its paragraph and every card its first sentence. Days 1, 31 and 60
  of every program show two lines (UI render test). Checked on the phone in both themes.

### 2. Home-screen shortcut
- A manifest `shortcuts` entry, "Today's workout", opening `./#today`. The `#today` route resolves to the
  next day not done in the program you opened last, or the first program if there isn't one, and replaces
  the address with that day's (`#p-<pid>-d<n>`). It uses Program Progress `nextDay`. With every day done,
  it opens the program page.
- Files: `manifest.webmanifest`, `app/views.js`, `tests-ui/shortcut.spec.js`, `tests/build.test.js`.
- **Test first:** a UI test: tick days 1–2 of Iron PPL, open it, go to `#today` → Iron PPL day 3. Also a
  build test that the manifest has the shortcut.
- **Done when:** the shortcut shows on a long-press of the installed app icon (Android), and `#today`
  behaves as above.

### 3. Load programs when opened, fully offline
- **Build:** `index.html` inlines only the program summaries. Each program's days are written to
  `programs/<id>.json` and deployed with the site. First download: about 1.7 MB → about 0.2 MB.
- **Program Catalogue:** a second adapter, `fetched(summaries, { fetch, cache })`. `load(pid)` fetches the
  program file and stores it in the offline cache; offline, it reads the cache.
- **Offline:** after the first screen, the app loads every program quietly in the background, on any
  network, starting with the open program and the ones with progress. Every program then works offline.
  The service worker already falls back to its cache.
- **Page:** the program, day and exercise pages show "Loading…" until their program is loaded, then draw. Stats
  wait for the programs they count.
- Files: `build.js`, `app/programs.js`, `tests/programs.test.js`, `app/main.js`, `app/views.js`, `sw.js`,
  `.github/workflows/deploy.yml` (collect `programs/`), `tests-ui/fixtures.js`, `tests-ui/offline.spec.js`, `tests/build.test.js`.
- **Test first:**
  - the fetched adapter with a fake fetch and cache: one fetch per program, cache written, cache used
    offline, and a failed load that retries later;
  - a build test: `index.html` has no days and each program file does.
- **Done when:**
  - every existing UI test passes (the fixture waits for loading);
  - a UI test opens a program, goes offline, reloads, and still opens every program;
  - the first download is under 0.3 MB.

### 4. Rounds (#17)
- **Program Progress** gains past rounds: `{ done, swaps, past: [{ round, done, endedAt }] }`. Round
  number = `past.length + 1`. The cloud document gets a `past` field; the codecs, merges and backups carry
  it, and older documents read as round 1.
- **Start again any time:** the program page offers "Start Round N". It archives the current days
  (kept as they were), clears `done`, and first shows each rest-of-program swap with **Keep** / **Back to
  the original**.
- **Everywhere:** "Round 2 · Day 1 of 60" on the program and day pages when the round is above 1.
- **Stats:** entries carry their round, and all rounds count by default. With one program picked, a Round
  switch narrows to one round (the stats report's scope).
- Files: `app/progress.js`, `app/store.js`, `app/backup.js`, `app/stats.js`, `app/views.js`, `app/main.js`, their tests, `tests-ui/rounds.spec.js`.
- **Test first:**
  - Program Progress: start a round (archive, clear, onward swaps kept or dropped as chosen);
  - the codec with and without `past`;
  - merges keep every past round;
  - stats entries per round.
- **Done when:** on the phone you start Round 2, review the swaps, and see "Round 2 · Day 1 of 60". Round 1's
  days still count in stats, a Round switch narrows them, and a backup round-trips the rounds.

## Challenge round
- **Weakest assumption:** that loading programs later won't break the flows that assume they're there.
  I read who needs a program's days synchronously: the program and day pages (the open program), the
  exercise page ("days used in this program"), and stats (every program with done days). **Plan changes:**
  the page shows "Loading…" and redraws on arrival; the background loader starts with the open program and
  the programs with progress; and the UI fixture waits for loading to finish, so tests don't race it.
- **What I hadn't read:** how the service worker behaves on the very first visit. It installs asynchronously,
  so programs fetched before it takes control aren't in its cache. **Plan change:** the page writes each
  loaded program into the same cache itself (Cache API), so offline works right after the first visit and
  doesn't wait for the service worker.
- **The lazier version:** skip load-on-open until Phase 5 actually grows the library. Not proposed: Noam
  chose this order, and today's 1.7 MB first load on mobile data already pays for it. Rounds come after it
  because their stats need every round's days, which load-on-open changes.
